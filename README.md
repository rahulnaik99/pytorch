# Trading LLM Fine-Tune Pipeline

Fine-tune a 4B LLM (Nemotron Bolt) to make NSE equity trading decisions using multi-timeframe technical analysis and quarterly fundamental data.

**Stack**: PyTorch + HuggingFace PEFT LoRA + trl SFTTrainer + MLflow  
**Hardware**: MacBook M5 (Apple Silicon MPS) — also works on NVIDIA CUDA  
**Universe**: NSE Banking sector — 19 stocks + Bank Nifty index

---

## How it works

```
1. fetch_fundamentals.py — one-time download: 16 quarters per stock → data/fundamentals/*.json
2. pipeline.py   — 1H+5M intraday candles + VIX + fundamentals → LLM trade → SQLite
3. splitter.py   — SQLite → quality-filtered JSONL (train / val / test)
4. train.py      — LoRA fine-tune the model on that JSONL
5. evaluate.py   — measure model quality + trading metrics on held-out test set
6. serve.py      — local REST endpoint to test the fine-tuned model
```

## Quick start

```bash
pip install -r requirements.txt

# 0. Download fundamental data (run once; refresh when new quarter drops)
python fetch_fundamentals.py --all-banking
# or specific stocks:
python fetch_fundamentals.py HDFCBANK ICICIBANK CANBK

# 1. Data generation — single stock
SYMBOL=CANBK START_DATE=2024-01-01 END_DATE=2024-06-30 python pipeline.py

# 1. Data generation — multiple stocks (banking sector)
SYMBOLS=HDFCBANK,ICICIBANK,CANBK,SBIN COUNT=100 WORKERS=4 python pipeline.py

# 2. Split to JSONL
python splitter.py

# 3. Train (smoke-test: EPOCHS=1, full run: EPOCHS=3)
EPOCHS=1 python train.py --train data/trading_train.jsonl --val data/trading_val.jsonl

# 4. View loss in browser
mlflow ui   # → http://localhost:5000

# 5. Merge adapter → fused model
python train.py --merge --adapter output/nemotron-lora

# 6. Evaluate
python evaluate.py --test data/trading_test.jsonl \
    --model output/nemotron-lora/fused_model --pnl-from-meta

# 7. Serve + test
HF_MODEL=output/nemotron-lora/fused_model python serve.py
```

## Files

| File | Purpose |
|------|---------|
| `pipeline.py` | Data generation loop — one SQLite row per (symbol, date, slot) |
| `technicals.py` | `TechnicalsAnalyzer` — 1H+5M EMA, VWAP, S/R zones, VIX, structure |
| `fundamentals.py` | `FundamentalAnalyzer` — load JSON, look-ahead filter, QoQ % summarization |
| `fetch_fundamentals.py` | One-time yfinance downloader → `data/fundamentals/<SYMBOL>.json` |
| `prompts.py` | Canonical `SYSTEM_PROMPT` + `build_prompt_mtf()` — single source of truth |
| `splitter.py` | SQLite → JSONL with quality filter, dedup, walk-forward split |
| `train.py` | LoRA training + adapter merge |
| `inference.py` | HuggingFace model inference with lazy model cache |
| `evaluate.py` | Model quality metrics + trading P&L metrics |
| `serve.py` | Ollama-compatible local REST server for the fine-tuned model |
| `debug.ipynb` | Notebook: step through one sample — candles → technicals → fundamentals → prompt → decision → outcome |

## Data

| Path | Contents |
|------|----------|
| `data/prices/<SYMBOL>.csv` | Minute-level OHLCV per stock — `date, open, high, low, close, volume` |
| `data/prices/INDIAVIX.csv` | VIX intraday — `Ticker, Date/Time, ..., Open, High, Low, Close` |
| `data/fundamentals/<SYMBOL>.json` | 16 quarters of balance sheet per stock (generated by `fetch_fundamentals.py`) |
| `trading_agent.db` | Generated trade decisions (SQLite, cumulative, dedup enforced) |
| `data/trading_*.jsonl` | Train / val / test splits |

> **Fundamental data**: each stock has `data/fundamentals/<SYMBOL>.json` with 16 quarters of NII, PAT, Total Assets, Equity, and shareholding pattern. Values stored in ₹ Crore; the pipeline converts to QoQ % changes before feeding the LLM — no raw ₹ values in prompts. BANKNIFTY is an index and has no fundamental JSON.
>
> **Adding a stock**: add the symbol to `BANKING_SYMBOLS` in `pipeline.py`, run `python fetch_fundamentals.py <SYMBOL>`, and place `data/prices/<SYMBOL>.csv` minute-bar file.

## Configuration (env vars)

```bash
# Data generation
SYMBOL=CANBK                          # single NSE symbol
SYMBOLS=HDFCBANK,ICICIBANK,CANBK      # multiple symbols (overrides SYMBOL)
START_DATE=2024-01-01
END_DATE=2024-12-31
COUNT=100                             # samples per symbol
OLLAMA_MODEL=hf.co/nvidia/NVIDIA-Nemotron-3.5-Bolt-E4B-4GB:Q4_K_M
DATA_SOURCE=csv                       # "csv" or "yfinance"
WORKERS=4                             # parallel workers

# Realistic trade mechanics
POST_REASONING=1                      # second LLM call to explain outcome (default 0)
BACKFILL_REASONING=1                  # re-run on existing rows to fill post_reasoning

# Training
BASE_MODEL=nvidia/Nemotron-Mini-4B-Instruct
OUTPUT_DIR=output/nemotron-lora
EPOCHS=3
LORA_R=16

# Inference (after training)
HF_MODEL=output/nemotron-lora/fused_model
```
